## Findings requiring integrated proof

1. **Browser input delivery is untested by the current browser runner.** `scripts/gallery-browser-check.cjs` rotates with E, clicks OtherWall and authoring controls, and records keyboard walking. It sends no drag or horizontal wheel event. `navigation_check.gd` proves native `Input.parse_input_event` dispatch into a directly mounted viewer, but bypasses the browser canvas and `crt_display.gd` coordinate/gesture adapter. A lost horizontal-wheel event or wrongly transformed drag can therefore pass both suites. Before claiming mouse/trackpad support, extend the existing browser runner with a real drag and `mouse.wheel({deltaX: ...})`, assert a changed settled view, and verify that release over artwork opens nothing. Preserve plain-click artwork proof. A physical trackpad was not tested; browser horizontal-wheel transport is the automated proxy.
2. **The entrance assertion does not prove visible character animation.** `navigation_check.gd` accepts position advancement and `_kid_t > 0`. These also pass when `visitor.gd` receives an empty walk list and renders its static Muse anchor. The current generated-visitor loader explicitly allows that fallback. Retain the movement check, but the character's primary acceptance must inspect delivered frames during real movement, then require a stable resting pose, camera-relative facing changes, look and wave completion. Empty/missing motion must fail for the intended reason before calling this an animation regression test. Screenshot/clip review remains necessary for hand/head quality and cycle seams.
3. **Native portal roundtrips do not prove pointer navigation to the door.** `navigation_check.gd` calls `_walk_to` after staging next to each exit. This is useful collision and return-destination coverage; it bypasses floor-ray picking and actual key transport. `_clamp` and `_painting_shown` assertions likewise test private predicates, not attempted wall movement or art picking. Extend the same navigation scenario with delivered movement/pointer events and assert the resulting space/position and absence of detail. Do not delete existing logic proof until stronger delivery coverage is in hand.
4. **The quiet-stack GPU test has a deliberately narrow scope.** `final_render_check.gd::check_quiet_stack` uses a full-viewport quiet rectangle and the CRT shader's default zero curvature. It verifies pixel preservation and an effect outside the exemption after disabling the rectangle. It cannot detect wrong gallery-rectangle publication, a curved-edge mismatch, browser resizing, or gallery bleed into neighboring desktop pixels. Keep this shader check; inspect the actual exported shell at two browser sizes, including gallery corners and adjacent shell pixels. Do not describe the unit-sized result as full-shell conformance.

All four production paths have real callers: viewer `_process`/`_gui_input`, browser canvas input through `crt_display._input`, and the shell's displayed CRT/haze stack. There is no test-only production export to remove. These contracts are new in #135; prior #132 tests protect painting access and baked geometry, not browser orbit delivery or generated motion. Risks are missed navigation/animation failures and false rendering claims. Smallest follow-up surface: the existing native navigation harness and browser runner, not another framework or duplicate helper suite.

## Retain, with accurate claims

- **GPU versus CPU RGB6/copy-filter comparison:** although the formulas resemble each other, the independent contract is the pinned Dolphin/Animal Crossing arithmetic documented in [render research](../../research/gallery-final-render-overlay.md). GPU sampling, edge clamping, interpolation and precision can fail while the CPU reference succeeds. Retain all three filter strengths and black/white checks; this proves arithmetic, not aesthetic equivalence to a compressed video.
- **All-artwork real-event test:** `dollhouse_shot.gd` reads actual room records and clicks each painting; exact opened tags protect all 23 artworks. Its old instant-turn timing failed after eased orbit (8/23), and bounded waits for actual turn settlement/detail closure restored 23/23 without dropping assertions. Evidence: `/tmp/gallery-entry-post.log` and `/tmp/gallery-entry-artwork-regression.log`. This was an invalid timing assumption, not justification to weaken artwork acceptance.
- **Route stress and half-visible picking:** `shot.gd` retains distinct risks: bench routing over 300 seeded walks and clicking a clipped painting. Its expected clamp endpoint comes from the runtime helper, so that fuzz loop tests reachability of legal endpoints, not independent correctness of wall limits. Navigation collision checks cover a separate risk.
