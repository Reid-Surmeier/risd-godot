## Q1. ac-decomp: does the player ever hop, fall or land?

**Answer (VERIFIED): there is no player-controlled jump. There are, however, many authored hop and landing clips: chair, bed, boat, table pickup and the pitfall climb-out. The keyframe system has no scale channel (VERIFIED):
- Per-channel flags exist only for root TRANS_X/Y/Z and per-joint ROT_X/Y/Z. The joint struct holds only a rest translation, and the animation struct holds flag, data, key and fixed tables plus a frame count ([c_keyframe.h#L17-L57](https://github.com/ACreTeam/ac-decomp/blob/09ca8e8b5b24e6ab44047ee980cf0088ad7ecb4c/include/c_keyframe.h#L17-L57)).
- `play()` writes three root translations, then three rotations per joint (value×0.1°) ([c_keyframe.c#L428-L546](https://github.com/ACreTeam/ac-decomp/blob/09ca8e8b5b24e6ab44047ee980cf0088ad7ecb4c/src/c_keyframe.c#L428-L546)). Keys are (frame, value, tangent), interpolated with Hermite, tension Δframe/30 ([#L179-L253](https://github.com/ACreTeam/ac-decomp/blob/09ca8e8b5b24e6ab44047ee980cf0088ad7ecb4c/src/c_keyframe.c#L179-L253)).
- Draw is `T(trans)·Rz·Ry·Rx` per joint, and non-root joints use their rest translation ([#L708-L806](https://github.com/ACreTeam/ac-decomp/blob/09ca8e8b5b24e6ab44047ee980cf0088ad7ecb4c/src/c_keyframe.c#L708-L806), [sys_matrix.c#L384-L469](https://github.com/ACreTeam/ac-decomp/blob/09ca8e8b5b24e6ab44047ee980cf0088ad7ecb4c/src/system/sys_matrix.c#L384-L469)). The player's pre-draw hook only edits the head joint ([m_player_draw.c_inc#L1-L61](https://github.com/ACreTeam/ac-decomp/blob/09ca8e8b5b24e6ab44047ee980cf0088ad7ecb4c/src/game/m_player_draw.c_inc#L1-L61)).
- Morph is a crossfade from the **frozen last displayed pose**. It steps by 0.5/|counter| per update and the counter decays 0.5 per update, so a counter of -5 means 10 updates (0.167 s) and -3 means 6 updates ([#L281-L302](https://github.com/ACreTeam/ac-decomp/blob/09ca8e8b5b24e6ab44047ee980cf0088ad7ecb4c/src/c_keyframe.c#L281-L302), [#L367-L425](https://github.com/ACreTeam/ac-decomp/blob/09ca8e8b5b24e6ab44047ee980cf0088ad7ecb4c/src/c_keyframe.c#L367-L425)).
- Root motion: `AnimationMove` turns root-Y deltas into actor Y × scale when TRANS_Y is set ([#L1165-L1201](https://github.com/ACreTeam/ac-decomp/blob/09ca8e8b5b24e6ab44047ee980cf0088ad7ecb4c/src/c_keyframe.c#L1165-L1201), [#L1223-L1340](https://github.com/ACreTeam/ac-decomp/blob/09ca8e8b5b24e6ab44047ee980cf0088ad7ecb4c/src/c_keyframe.c#L1223-L1340)).
- The body mesh loads one joint matrix per vertex batch, and triangles stitch across batches, i.e. rigid single-matrix vertices ([boy_model.c#L38-L53](https://github.com/ACreTeam/ac-decomp/blob/09ca8e8b5b24e6ab44047ee980cf0088ad7ecb4c/src/data/model/boy_model.c#L38-L53); INFERRED from GBI load semantics).
- Code search on the default branch finds `Matrix_scale` only in held-item files (`m_player_item.c_inc`, `m_player_item_balloon.c_inc`). This is unpinned (INFERRED: no body squash or stretch).
