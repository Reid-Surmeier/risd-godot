# Viewer catalogue identity audit — 2026-09-28

## Finding

The twenty thumbnail slots are tied to exact local source pixels below. **None has a verified RISD Museum object identity.** The four scan source names are timestamps, and the sixteen other thumbnails are regions of one owner-supplied composite panel. Neither is an accession number or a source record. The current `APPEARANCE` strings are visual descriptors, not museum titles. This report is an evidence checkpoint for [catalogue ticket #169](https://github.com/Reid-Surmeier/risd-godot/issues/169); the title/department/description acceptance gate remains open.

The [RISD Museum Collection API documentation](https://risdmuseum.org/art-design/projects-publications/articles/risd-museum-collection-api) provides a public object endpoint and documents `title`, `description`, `objectNumber`, `images`, `url`, `publicDomain`, and `type`. It does **not** document a department field. Search terms and visual resemblance can suggest candidates, but the museum record image or a sourced accession must establish a match before any field is copied. `type` is not a substitute for department. The API's public-domain flag concerns the museum's object image; it does not establish redistribution rights for the owner-supplied panel or Proton scans.

## Reproduce thumbnail hashes

Run this from the repository root with Pillow installed; the source arrays and regions are in [`catalogue.gd`](../../modules/sculpture_viewer/catalogue.gd). For a panel cell `c`, use `index=c-1`, `x=CELL_X[index % 8]`, `y=CELL_Y[index // 8]`, then hash `Image.open(panel).convert("RGBA").crop((x,y,x+216,y+200)).tobytes()`. For a scan, hash the `*-front.png` file bytes. This audit asserted 20 distinct slot IDs and verified all region bounds against the 2100×3360 panel.
