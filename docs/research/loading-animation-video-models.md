# OpenRouter video model for the five-second loader test

Checked 2026-09-22 against OpenRouter's [live video model catalog](https://openrouter.ai/api/v1/videos/models), [video API guide](https://openrouter.ai/docs/guides/overview/multimodal/video-generation), [Seedance 2.5 review with request examples](https://openrouter.ai/blog/insights/seedance-2-5-review/), and model pages. The model comparison itself made no generation request.

Live diagnostic on 2026-09-22: two separate Mini test Runs ended without jobs. The second Run, after the adapter was changed to preserve sanitized HTTP diagnostics, recorded a concrete HTTP 400: `input_references[0].video_url.url: Only HTTPS URLs are allowed.` Its local MP4 had been encoded as a `data:video/mp4;base64,...` URL by the older adapter. That transport defect, not the choice of Mini, caused the confirmed rejection. Both Runs remain possibly spent and reconciliation-only; neither will be retried. Evidence: `artifacts/image-generation/runs/run-3b0caa0640227b9f5d9099f2/failure.json` and `image-work/loading-animation-test/provenance.json`. A replacement request requires a new hash-locked HTTPS URL for the short crop.

## Input correction

OpenRouter's general guide describes `input_references` using image examples, but its newer [first-party Seedance review](https://openrouter.ai/blog/insights/seedance-2-5-review/) explicitly shows a `video_url` and an `image_url` together in that field. It says video and audio references work for **all Seedance generation 2 models**, including Mini and 2.5. The indexed [video request API reference](https://openrouter.ai/docs/api/api-reference/video-generation/create-videos) likewise says `input_references` accepts image, audio, and video assets, although that page currently returns 404 on direct access. Thus the earlier inference that OpenRouter could not pass a motion-reference video was incorrect. These references guide the output; they do not pin an exact frame. If `frame_images` is also present, it takes precedence and the reference assets have no visible effect, according to the [Seedance review](https://openrouter.ai/blog/insights/seedance-2-5-review/).

The OpenRouter API example sends a video and still together in **`input_references` only** (not `frame_images`), but this tool's current Generation seam admits video-only motion references or first/last stills, not a mixed set. For the present study, send the short Instagram crop as `{ "type": "video_url", "video_url": { "url": "<accessible HTTPS MP4 URL>" } }`, describe the white screenshot in the prompt, and use `generate_audio: false`. Do not claim the screenshot was submitted as an anchor. Supporting the mixed input is separate interface work. [Source](https://openrouter.ai/blog/insights/seedance-2-5-review/).

Prices are for one five-second clip, calculated from the [live catalog](https://openrouter.ai/api/v1/videos/models) on 2026-09-22. Seedance uses `(width × height × 24 × seconds) / 1024` output tokens; the video-reference rate applies when a video reference is provided without `frame_images`. Actual billing should be checked from the completed job's `usage.cost`. [Source](https://openrouter.ai/blog/insights/seedance-2-5-review/).

The live catalog confirms all four accept a five-second clip and a square output; Mini and 2.5 accept 480p/720p, Kling Standard 720p, and Wan 3.0 480p/720p/1080p. OpenRouter's [Seedance review](https://openrouter.ai/blog/insights/seedance-2-5-review/) specifically identifies Wan 3.0 and Kling v3 as image-reference-only alternatives. OpenRouter has no published loader-specific fidelity test here; precision on the dots, glow, and lettering must be judged from an output clip rather than inferred from model branding.

## Recommendation

Use **Seedance 2.0 Mini, five seconds, 480×480**, with the HTTPS Instagram motion crop as the sole current model reference, no `frame_images`, and audio disabled. The failed attempt is evidence of a data-URL transport rejection, not that Mini lacks motion-reference support. Keep the request payload, HTTP diagnostic, job ID if returned, and final `usage.cost`; neither ambiguous prior Run is retryable. Escalate to Seedance 2.5 only if a successfully retrieved Mini clip visibly fails the motion/look test. The 2.5 model's documented advantage is longer, richer footage workflows; it does not add a required input capability for this five-second loader.
