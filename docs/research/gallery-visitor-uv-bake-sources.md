# Visitor UV bake: source-backed minimum

Research for the existing skinned visitor, 2026-09-27. This is an implementation recipe, not evidence that the resulting GLB already renders correctly. The repository's `scripts/playtest.sh` pins Godot 4.7.2 and `scripts/check-gallery.sh` selects `gl_compatibility`; use the [Godot 4.7 renderer reference](https://docs.godotengine.org/en/4.7/tutorials/rendering/renderers.html) when judging the result.

1. **Limit the experiment to one existing mesh surface.** Keep its armature, vertex weights and animation hierarchy. Give that mesh its own copy of the shared material before changing nodes, because the current Rogue body meshes share one material and atlas; this isolation is a repository-specific inference from the inspected asset in [the grounded visitor study](gallery-grounded-3d-character-plan.md). Use its existing UVs if the chosen surface has non-overlapping islands with enough texel space; otherwise make one non-overlapping UV set and explicitly select it for the target image. Cycles requires a mesh UV map and an active Image Texture node with an image as the bake target. Its image-bake margin extends island borders to avoid texture seams under filtering and mipmaps. [Blender 4.3 Cycles baking](https://docs.blender.org/manual/en/4.3/render/cycles/baking.html), [Blender 4.3 UV operators](https://docs.blender.org/manual/en/4.3/modeling/meshes/editing/uv.html).
2. **Bake a color test first.** In Cycles, add a *new* image to an Image Texture node in the copied material and make that node active; leave the original color image connected as the source during baking. Select only the chosen mesh. Bake `Diffuse` with **Color** enabled and **Direct/Indirect** disabled for unlit base color, or `Emit` if the source is deliberately routed through Emission. Save the baked image as PNG, then connect that image to Principled BSDF **Base Color** and export GLB with UVs, materials, skinning and required animations. Blender's exporter recognizes an Image Texture connected to Base Color; binary GLB carries images and mesh data in one file. [Blender 4.3 Cycles baking](https://docs.blender.org/manual/en/4.3/render/cycles/baking.html), [Blender 4.3 glTF exporter](https://docs.blender.org/manual/ja/4.3/addons/import_export/scene_gltf2.html), [Godot 4.7 GLB import](https://docs.godotengine.org/en/4.7/tutorials/assets_pipeline/importing_3d_scenes/available_formats.html).
3. **Treat AO as a separate map.** If the color test succeeds, bake `Ambient Occlusion` to a second image on the same UVs. To export it as glTF AO in Blender 4.3, attach its Image Texture to the `Occlusion` input of the exporter-recognized **`glTF Material Output`** node group. glTF reads AO from the image's **red channel** and applies it to **indirect ambient light**, not direct light; its texture coordinate set defaults to `TEXCOORD_0`. Multiplying AO into base color would darken direct light too, so it is a different look. The material AO map is distinct from screen-space AO. [Blender 4.3 glTF AO hookup](https://docs.blender.org/manual/ja/4.3/addons/import_export/scene_gltf2.html), [glTF 2.0 material and AO specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html), [Godot 4.7 BaseMaterial3D AO properties](https://docs.godotengine.org/en/4.7/classes/class_basematerial3d.html).
4. **Verify the transfer at each seam.** Inspect the exported GLB JSON for the chosen primitive's `TEXCOORD_0`, `JOINTS_0`/`WEIGHTS_0`, `material.pbrMetallicRoughness.baseColorTexture`, and (if attempted) `material.occlusionTexture`; check that the image bytes are present and that animation/skin counts remain unchanged. The glTF spec defines these vertex and material fields. Import the GLB in Godot and inspect the chosen surface's material for albedo texture and enabled AO texture, then compare the animated character in a matched Compatibility and browser capture with/without the new map. Godot recommends GLB, imports its embedded textures, and exposes `albedo_texture`, `ao_enabled`, `ao_texture`, and `ao_on_uv2` on BaseMaterial3D. A valid GLB alone cannot establish that AO is visible under this scene's ambient lighting. [glTF 2.0 specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html), [Godot 4.7 GLB import](https://docs.godotengine.org/en/4.7/tutorials/assets_pipeline/importing_3d_scenes/available_formats.html), [Godot 4.7 BaseMaterial3D](https://docs.godotengine.org/en/4.7/classes/class_basematerial3d.html).

**Caveats.** If the original atlas has mirrored/stacked UVs on the chosen mesh, an AO or asymmetrical color bake will overwrite distinct surface locations in the same pixels; unwrap that mesh before treating the result as usable. A new UV set must be bound to the texture and present in the exported primitive; glTF does not infer it from the image. Blender's node group name is version-sensitive: the older `glTF Settings` name seen in older manuals should not be copied into a 4.3 recipe. Godot 4.7's Compatibility renderer supports screen-space AO, but that is a separate renderer effect and does not validate an imported material AO map. [Blender 4.3 glTF exporter](https://docs.blender.org/manual/ja/4.3/addons/import_export/scene_gltf2.html), [glTF 2.0 texture coordinate requirements](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html), [Godot 4.7 renderer features](https://docs.godotengine.org/en/4.7/tutorials/rendering/renderers.html).
